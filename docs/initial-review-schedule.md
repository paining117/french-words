# 新词首次复习 · 1／3／5 天

> 2026-09-21：规则已改为按完成时的有效作答次数：3 次→5 天、4 次→3 天、≥5 次→次日；首次选错／不认识始终次日。三颗星尚未完成时暂排次日。重复打开未作答题不加次数，已有旧版完成词不会因启动而重新调度。正式 Review 已实现，正式评分后仅按 FSRS due。以下为旧版本记录，现行实现见 [交付报告](phase3-report.md)。

用户指定的规则：

| 学习记录 | 首次复习 |
| --- | --- |
| 任意一次出现过“不认识”，包括首次模糊、后来不认识 | 1 天后 |
| 首次模糊，后来认识，且从未选择不认识 | 3 天后 |
| 首次认识 | 5 天后 |
| 一直模糊、尚未确认认识 | 暂按 1 天后 |

“出现过不认识”的优先级最高；之后即使两次认识完成强化，也不会改成更晚的首次复习。当前轮内强化与正式待复习队列独立，仍可当天反复回忆。

日期以该词最近一次实际 Study 评分所在本地日期为基准，取 1／3／5 天后的本地 00:00，让用户在对应日即可复习。重新打开 App 不使用打开时间重新计日，因此不会把安排不断向后推。如果学习跨到新的一天才继续评分，则从新的实际学习日重新计算。

## 与 FSRS 的关系

仍先调用 ts-fsrs 更新记忆状态，随后应用首次复习产品规则，同步保存 cards.due_at 与完整 Card JSON 的 due、scheduled_days。stability、difficulty、reps、lapses、state、学习步骤及 last_review 保留库的输出；真实评分 Log 不改写、不补造。

这是首次复习日期的明确覆盖策略，不声称 1／3／5 天是 FSRS 自然计算的结果。出现正式 context=review 的记录后不再应用本策略，后续长期复习由正式 Review 的 FSRS 调度负责。正式 Review UI 仍未在本阶段实现。

应用启动时根据真实 Study 日志更新今天已学、尚未正式复习的词，让已经完成的今日总结也能显示新规则。缺少 Study 日志、历史其他日期或已正式复习的卡不会被这次启动更新擅自重排。

2. 在本轮总结中检查：首次认识 → 5 天后；首次模糊后认识 → 3 天后；出现过不认识 → 1 天后。
3. 今天的新词不应立刻增加首页待复习数量；此前已到期的旧词仍会计入。
4. 再次退出重进，日期不应随重开顺延，既有学习记录仍在。
